## Stacking execution (when you say go)

1. `git checkout feature/f1.3-mega-reports`
2. `git checkout -b f1.3-pr1-foundation` → cherry-pick / manually stage PR1 files → commit → push
3. `gh pr create --base feature/f1.3-mega-reports --head f1.3-pr1-foundation`
4. `gh stack submit` (or repeat manually for next PR)
5. Repeat for pr2–pr6, each branch based on prior tip
6. Final: `gh pr create --base main --head feature/f1.3-mega-reports` (the trunk PR)

## Risk / things to flag

- **MegaReportView imports all 13 sections** — confirmed. PR6 cannot land standalone.
- **Charts are imported by 7 sections** — confirmed (KpiCover ×2, Income, Savings, Home, Common, Personal, CcPaydowns). Shipped in PR1.
- **`mega_pdf.py` imports `mega_builder`** — confirmed. PR2 needs PR1.
- **`PartnerSplitTable` is shared by Home/Savings (PR3) + Common/Personal (PR4)** — PR3 imports a not-yet-existent file unless we bundle it differently. Decision: ship `PartnerSplitTable` in PR4; Home/Savings in PR3 won't render without it. Workaround: PR3 still merges because the sections aren't wired into a page yet (no `MegaReportView` consuming them) — they'll just be unused exports. Alternative: move `PartnerSplitTable` to PR1 as an additional chart-like primitive. **Recommendation: move to PR1** to keep PR3 self-renderable.
- **`mega/build_mega.py` edit adds `_trip_label`** — backend change reviewed in PR6 (alongside View) since that's the consumer. Fine.
- **`accounting.py` edit preserves txn `labels`** — backend infra tweak, also PR6. Tests for backend pipeline land in PR6.
- **`pnpm-lock.yaml` is large** — keep with PR1. Smaller per-PR diff.
